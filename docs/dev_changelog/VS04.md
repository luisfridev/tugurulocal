### Cambios realizados y motivo

- Instalado `spatie/laravel-sitemap:^8.2`, versión resuelta 8.2.0, licencia MIT. Composer añadió `spatie/crawler` 9.4.2, `spatie/robots-txt` 2.5.5 y `symfony/dom-crawler` 8.1.5; cero actualizaciones y cero eliminaciones de dependencias anteriores. Se omitieron los scripts generales de Composer y se ejecutó `package:discover` para registrar el proveedor, sin publicar recursos ni configuración del paquete.
- `BuildPublicSitemap` concentra la selección existente y construye `Sitemap`/`Url` mediante la API manual. Reutiliza las consultas públicas, la indexabilidad y el resolvedor de URLs; el controlador solo genera la respuesta. Se retiró la plantilla XML propia para no mantener dos generadores.
- GET/HEAD `/sitemap.xml` conserva `application/xml; charset=UTF-8` y `Cache-Control: no-store, private`, normalizado por Symfony. Cada petición consulta la elegibilidad vigente, sin crawler, archivo estático, cron ni caché persistente. No se añaden `lastmod`, prioridades, frecuencias ni módulos futuros.
- Las pruebas reutilizadas verifican el conjunto exacto de URLs, incluido un negocio adicional en la misma categoría/zona para detectar duplicados. Se comprueban cabeceras GET/HEAD, cuerpo HEAD vacío, ausencia de campos opcionales y parámetros arbitrarios, y retirada/reaparición por visibilidad de ciudad o aprobación editorial. Las pruebas existentes de slugs verifican que solo aparezca el destino vigente.
- README, diseño técnico y stack describen la integración local. `robots.txt`, canonical, `noindex` y reglas de redirección conservan sus contratos. Esta continuación no crea migraciones ni modifica el contenido de la base principal.

### Implementación que se entrega

- URLs compartidas para enlaces, canonical y sitemap; canonical propio para páginas sin filtros, base del contexto para filtros y descarte de parámetros desconocidos. DEMO, vacíos y filtros conservan `noindex`; las previsualizaciones privadas no generan datos estructurados.
- Metadatos Open Graph/Twitter coherentes y `BreadcrumbList` con los mismos nombres y destinos que el componente visible. El JSON-LD usa escape de etiquetas y caracteres especiales y refleja descripción/FAQ visibles. El breadcrumb de ficha pasa a Inicio, Negocios y nombre de ficha: evita duplicar Inicio/ciudad y facilita volver al directorio.
- Cambios de slug solo en fichas. `slug_redirects` reserva cada origen y referencia la ficha; los cambios sucesivos redirigen en un salto al slug vigente. Si el destino deja de ser público, responde 404 sin `Location`. No se redirigen subrutas auxiliares ni URLs heredadas; las solicitudes de sitemap/redirección no registran visitas.

- Nueva cobertura de seguridad del rollback: una migración inversa con reservas existentes debe fallar sin borrar la reserva ni romper su 301. No se modificó la lógica funcional en esta continuación de cierre.

La migración `2026_10_23_072127_create_slug_redirects_table` figura aplicada localmente en lote 5. La comprobación no volvió a migrar ni reinició la base.
